**Date:** 16 October 2026

**Topics:** COUNT, SUM, AVG, MIN, MAX, DISTINCT with Aggregates, GROUP BY, HAVING, WHERE vs HAVING, NULL Handling

### 1. What are SQL aggregate functions, and how do COUNT(), SUM(), AVG(), MIN(), and MAX() work?

**Answer:**

An **aggregate function** processes a collection of input rows and returns a single result. Aggregates are useful for summarizing business data, such as employee headcount, total payroll, average salary, and salary extremes.

| Function | Purpose | Example |
|---|---|---|
| `COUNT(*)` | Counts all input rows | Total employees |
| `COUNT(column)` | Counts non-NULL values in a column | Employees with recorded bonuses |
| `SUM(column)` | Adds non-NULL numeric values | Total salaries |
| `AVG(column)` | Calculates the mean of non-NULL numeric values | Average salary |
| `MIN(column)` | Returns the smallest non-NULL value | Lowest salary |
| `MAX(column)` | Returns the largest non-NULL value | Highest salary |

**Example:**

```sql
SELECT
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary,
    ROUND(AVG(salary), 2) AS average_salary,
    MIN(salary) AS minimum_salary,
    MAX(salary) AS maximum_salary
FROM employee_day3;
```

This query produces one summary row for the entire table. `ROUND()` makes the displayed average easier to read.

**Important Points:**

- `COUNT(*)` includes every row, even if some column values are `NULL`.
- `COUNT(column)` and the numeric aggregates ignore `NULL` values in their input column.
- Without `GROUP BY`, the aggregates summarize the entire filtered input as one group.
- Except for `COUNT`, an aggregate over no non-NULL input values generally returns `NULL`.

### 2. What is the difference between COUNT(*), COUNT(column), and COUNT(DISTINCT column)?

**Answer:**

These three forms count different things. Understanding them prevents mistakes when columns contain repeated or missing values.

| Expression | What it counts | NULL handling |
|---|---|---|
| `COUNT(*)` | All rows | Includes rows containing NULLs |
| `COUNT(bonus)` | Rows where `bonus` is not NULL | Excludes NULL bonuses |
| `COUNT(DISTINCT department)` | Unique non-NULL department values | Excludes NULL and duplicates |

**Example:**

```sql
SELECT
    COUNT(*) AS total_employees,
    COUNT(bonus) AS employees_with_bonus_value,
    COUNT(DISTINCT department) AS department_count
FROM employee_day3;
```

A bonus of `0` is a known value and is counted by `COUNT(bonus)`; a `NULL` bonus is missing and is not counted.

**Important Points:**

- `DISTINCT` inside an aggregate removes duplicate non-NULL inputs before aggregation.
- `COUNT(DISTINCT city)` counts unique known cities, not employee records.
- `COUNT(*)` is the correct choice when the requirement is to count rows.
- `COUNT(bonus)` does not mean “employees receiving a positive bonus”; it also counts zero bonuses.

### 3. What is GROUP BY, and how does it summarize rows by one or more columns?

**Answer:**

`GROUP BY` divides rows into groups based on the values of selected expressions. Aggregate functions then calculate a result separately for each group. For example, grouping by department allows PostgreSQL to calculate department-wise headcount and payroll.

**Example:**

```sql
SELECT
    department,
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary,
    ROUND(AVG(salary), 2) AS average_salary
FROM employee_day3
GROUP BY department
ORDER BY department ASC;
```

This returns one row per department rather than one row per employee.

**Grouping by multiple columns:**

```sql
SELECT
    department,
    city,
    COUNT(*) AS employee_count
FROM employee_day3
GROUP BY department, city
ORDER BY department ASC, city ASC;
```

Each distinct department-and-city combination becomes a separate group.

**Important Points:**

- Every selected column that is not aggregated must generally appear in `GROUP BY` (subject to PostgreSQL's limited functional-dependency exception).
- `GROUP BY department, city` groups by combinations, not by the two columns independently.
- `GROUP BY` does not guarantee the order of the output; use `ORDER BY` explicitly.
- Rows with `NULL` grouping values are grouped together for that grouping expression.

### 4. What is HAVING, and how is it different from WHERE?

**Answer:**

`WHERE` filters individual rows **before** grouping. `HAVING` filters the resulting groups **after** aggregation. This distinction is essential when requirements involve both employee-level conditions and department-level totals or averages.

| Feature | WHERE | HAVING |
|---|---|---|
| Filters | Individual rows | Groups |
| Applied conceptually | Before `GROUP BY` | After `GROUP BY` |
| Typical condition | `salary >= 50000` | `COUNT(*) >= 3` |
| Aggregate conditions | Not permitted directly | Permitted |

**Example:**

```sql
SELECT
    department,
    COUNT(*) AS qualifying_employees,
    ROUND(AVG(salary), 2) AS average_salary
FROM employee_day3
WHERE salary >= 50000
GROUP BY department
HAVING COUNT(*) >= 3
ORDER BY average_salary DESC, department ASC;
```

First, the `WHERE` clause excludes employees earning less than 50,000. Next, PostgreSQL groups the remaining rows by department. Finally, `HAVING` retains only groups with at least three qualifying employees.

**Important Points:**

- Use `WHERE` to filter raw rows and `HAVING` to filter aggregate results.
- `WHERE COUNT(*) > 2` is invalid because aggregates cannot be used directly in `WHERE`.
- A query may use both `WHERE` and `HAVING`.
- In PostgreSQL, a SELECT-list alias generally cannot be referenced directly in `HAVING`; repeat the aggregate expression instead.

### 5. How do NULL values, DISTINCT, and ORDER BY affect aggregate queries?

**Answer:**

Accurate summaries require understanding how missing values, duplicate inputs, and output ordering interact with aggregate functions.

`SUM()`, `AVG()`, `MIN()`, and `MAX()` ignore `NULL` inputs. `COUNT(*)` counts all rows, whereas `COUNT(column)` counts only known values. `DISTINCT` can be placed inside supported aggregate functions to aggregate unique values rather than every occurrence.

**Example:**

```sql
SELECT
    department,
    COUNT(*) AS total_employees,
    COUNT(bonus) AS recorded_bonuses,
    COALESCE(SUM(bonus), 0) AS total_bonus,
    ROUND(AVG(salary), 2) AS average_salary,
    COUNT(DISTINCT city) AS cities_represented
FROM employee_day3
GROUP BY department
ORDER BY average_salary DESC, department ASC;
```

`COALESCE(SUM(bonus), 0)` displays zero when a department has no non-NULL bonus values. This is a reporting choice: it does not change the stored missing values.

**Example: DISTINCT within an aggregate**

```sql
SELECT
    COUNT(DISTINCT department) AS unique_departments,
    SUM(DISTINCT salary) AS sum_of_unique_salary_values
FROM employee_day3;
```

The second expression adds each distinct non-NULL salary amount once. It is **not** the total company payroll and should only be used when unique salary values are specifically required.

**Important Points:**

- `AVG(bonus)` averages only non-NULL bonuses; it does not automatically treat missing bonuses as zero.
- `COALESCE()` can substitute a display or calculation default for `NULL`, but the choice must match the question's meaning.
- `ORDER BY` sorts the grouped results; it does not change the aggregate values.
- Add a secondary sort key, such as `department ASC`, to make tied results deterministic.
