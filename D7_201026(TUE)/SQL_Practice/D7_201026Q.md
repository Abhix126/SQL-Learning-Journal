## 1. Theoretical Questions

### Q1. What is a subquery in SQL? What are its different types?

A **subquery** is a SQL query written inside another query. Its result is used by the outer query.

Subqueries can appear in `SELECT`, `FROM`, `WHERE`, and `HAVING` clauses.

**Types:**

| Type | Description |
|---|---|
| Scalar | Returns one value |
| Multi-row | Returns multiple rows |
| Correlated | References columns from the outer query |
| Nested | Contains another subquery |
| Derived table | Subquery used in the FROM clause |

**Example:**

```sql
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

Returns employees earning more than the company average.

**Key Points:**
- Subqueries are enclosed in parentheses.
- A subquery can contain another subquery.
- Scalar subqueries must return at most one row and one column.
- Subqueries can simplify complex filtering conditions.

### Q2. What is the difference between scalar and multi-row subqueries?

A **scalar subquery** returns a single value, while a **multi-row subquery** returns multiple rows.

**Scalar Subquery:**

```sql
SELECT name, salary
FROM employees
WHERE salary = (
    SELECT MAX(salary)
    FROM employees
);
```

**Multi-Row Subquery:**

```sql
SELECT name, department_id
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
    WHERE location = 'Bengaluru'
);
```

**Key Points:**
- Scalar subqueries support operators such as `=`, `>`, and `<`.
- Multi-row subqueries commonly use `IN`, `ANY`, or `ALL`.
- Using `=` with a subquery returning multiple rows causes an error.
- A scalar subquery returning no rows evaluates to NULL.

### Q3. What is a correlated subquery? How is it different from a non-correlated subquery?

A **correlated subquery** references a column from its outer query.

**Example:**

```sql
SELECT e.name, e.salary, e.department_id
FROM employees AS e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees AS e2
    WHERE e2.department_id = e.department_id
);
```

Returns employees earning more than their own department's average salary.

| Non-Correlated | Correlated |
|---|---|
| Independent of outer query | References outer query |
| Can execute independently | Depends on outer-row values |
| Often calculates a common result | Can calculate a result for each outer row |

**Key Points:**
- Correlated subqueries reference outer-query aliases.
- They are useful for group-specific comparisons.
- PostgreSQL may optimize their execution.
- JOINs and window functions can sometimes provide alternatives.

### Q4. What are IN, EXISTS, and NOT EXISTS? How do they differ?

`IN` checks whether a value belongs to a result set.

`EXISTS` checks whether a subquery returns at least one row.

`NOT EXISTS` checks whether a subquery returns no rows.

**IN Example:**

```sql
SELECT name
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
    WHERE location = 'Mumbai'
);
```

**EXISTS Example:**

```sql
SELECT e.name
FROM employees AS e
WHERE EXISTS (
    SELECT 1
    FROM projects AS p
    WHERE p.emp_id = e.emp_id
);
```

**NOT EXISTS Example:**

```sql
SELECT e.name
FROM employees AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM projects AS p
    WHERE p.emp_id = e.emp_id
);
```

**Key Points:**
- `IN` compares a value against a set.
- `EXISTS` checks row existence, not selected values.
- `NOT EXISTS` is useful for finding unmatched records.
- `NOT IN` requires caution when the subquery contains NULL values.

### Q5. What are ANY and ALL operators? How do nested subqueries work?

`ANY` compares a value against at least one value returned by a subquery.

`ALL` compares a value against every value returned by a subquery.

**ANY Example:**

```sql
SELECT name, salary
FROM employees
WHERE salary > ANY (
    SELECT salary
    FROM employees
    WHERE department_id = 2
);
```

Returns employees whose salary is greater than at least one salary in department 2.

**ALL Example:**

```sql
SELECT name, salary
FROM employees
WHERE salary > ALL (
    SELECT salary
    FROM employees
    WHERE department_id = 2
);
```

Returns employees whose salary is greater than every salary in department 2.

**Nested Subquery Example:**

```sql
SELECT name
FROM employees
WHERE department_id = (
    SELECT department_id
    FROM departments
    WHERE department_name = (
        SELECT department_name
        FROM departments
        WHERE department_id = 1
    )
);
```

**Key Points:**
- `> ANY` means greater than at least one returned value.
- `> ALL` means greater than every returned value.
- Empty result sets and NULL values can affect comparison results.
- Nested subqueries can contain multiple levels.
- Avoid unnecessary nesting when a simpler query is possible.

## 2. Practical SQL Questions

**Dataset Files:**
- `employee_day7.csv`
- `departments_day7.csv`
- `projects_day7.csv`

**Tables:**
- `employee_day7`
- `departments_day7`
- `projects_day7`

### Q1. Find employees earning above the company average salary.

Retrieve:
- `emp_id`
- `name`
- `department_id`
- `salary`

**Conditions:**
- Use a scalar subquery.
- Include employees earning strictly above the overall average salary.
- Sort by `salary DESC`, then `emp_id ASC`.

**Concepts:** Scalar Subquery, AVG(), WHERE

### Q2. Find employees working in departments located in Bengaluru or Hyderabad.

Retrieve:
- `emp_id`
- `name`
- `department_id`
- `salary`

**Conditions:**
- Use a multi-row subquery with `IN`.
- Retrieve department IDs from the departments table.
- Do not use JOIN.
- Sort by `department_id ASC`, then `emp_id ASC`.

**Concepts:** Multi-Row Subquery, IN

### Q3. Find employees earning above their department's average salary.

Retrieve:
- `emp_id`
- `name`
- `department_id`
- `salary`

**Conditions:**
- Use a correlated subquery.
- Compare each employee's salary with their own department's average.
- Exclude employees without departments.
- Sort by `department_id ASC`, then `salary DESC`.

**Concepts:** Correlated Subquery, AVG(), Outer Query References

### Q4. Find employees who are not assigned to any project.

Retrieve:
- `emp_id`
- `name`
- `department_id`
- `salary`

**Conditions:**
- Use `NOT EXISTS`.
- Include employees with no project assignments.
- Employees assigned only to Completed or Planning projects must be excluded.
- Sort by `emp_id ASC`.

**Concepts:** Correlated Subquery, NOT EXISTS

### Q5. Find employees earning more than every employee in the HR department.

Retrieve:
- `emp_id`
- `name`
- `department_id`
- `salary`

**Conditions:**
- Use a nested subquery to identify the HR department.
- Use `ALL` to compare salaries.
- Include employees from any department who satisfy the condition.
- Sort by `salary DESC`, then `emp_id ASC`.

**Concepts:** Nested Subqueries, ALL, Multi-Row Comparisons
