### 1. What is SQL, and how does it differ from a DBMS?

**Answer:**

SQL (Structured Query Language) is a declarative language used to define, retrieve, manipulate, and control data in relational database systems.

A **DBMS (Database Management System)** is software responsible for storing, organizing, retrieving, securing, and managing databases.

An **RDBMS (Relational Database Management System)** is a type of DBMS that organizes data into relations, commonly represented as tables containing rows and columns.

| Aspect | SQL | DBMS / RDBMS |
|---|---|---|
| Definition | Database query language | Database management software |
| Purpose | Defines and manipulates data | Stores and manages databases |
| Nature | Declarative language | Software system |
| Examples | SELECT, INSERT, UPDATE | PostgreSQL, MySQL, SQLite |

SQL is declarative because users specify **what data they want**, while the database engine determines how to retrieve it.

**Example:**

```sql
SELECT name, salary
FROM employees
WHERE salary > 50000;
```

The SQL statement specifies the required information, while PostgreSQL determines an execution strategy.

**Key distinction:** SQL is the language used to interact with a relational database, whereas an RDBMS is the software that manages it.

### 2. What are the major categories of SQL commands?

**Answer:**

SQL commands are commonly classified into five categories based on their functionality.

| Category | Full Form | Purpose | Commands |
|---|---|---|---|
| DDL | Data Definition Language | Defines database structures | CREATE, ALTER, DROP, TRUNCATE |
| DML | Data Manipulation Language | Modifies stored data | INSERT, UPDATE, DELETE |
| DQL | Data Query Language | Retrieves data | SELECT |
| DCL | Data Control Language | Manages access privileges | GRANT, REVOKE |
| TCL | Transaction Control Language | Manages transactions | BEGIN, COMMIT, ROLLBACK, SAVEPOINT |

**DDL Example:**

```sql
CREATE TABLE employees (
    emp_id INTEGER PRIMARY KEY,
    name VARCHAR(100),
    salary INTEGER
);
```

Creates a table named `employees`.

**DML Example:**

```sql
INSERT INTO employees (emp_id, name, salary)
VALUES (101, 'Amit', 65000);
```

Inserts a record into the table.

**DQL Example:**

```sql
SELECT *
FROM employees;
```

Retrieves all columns from the table.

**DCL Example:**

```sql
GRANT SELECT ON employees TO analyst;
```

Grants the SELECT privilege to an existing database role named `analyst`.

**TCL Example:**

```sql
BEGIN;

UPDATE employees
SET salary = 70000
WHERE emp_id = 101;

COMMIT;
```

Starts a transaction, modifies a record, and commits the change.

**Important:** These classifications are commonly used for learning SQL. They are not strict divisions of the SQL standard.

### 3. What is the difference between SELECT and WHERE?

**Answer:**

`SELECT` and `WHERE` are SQL clauses that perform different functions.

- `SELECT` specifies the columns or expressions to retrieve.
- `FROM` identifies the source table.
- `WHERE` filters rows according to specified conditions.

**Syntax:**

```sql
SELECT column1, column2
FROM table_name
WHERE condition;
```

**Example 1: Selecting Columns**

```sql
SELECT name, department
FROM employees;
```

Retrieves employee names and departments.

**Example 2: Filtering Records**

```sql
SELECT name, salary
FROM employees
WHERE salary > 50000;
```

Retrieves employees whose salaries exceed 50,000.

**Comparison Operators:**

| Operator | Meaning | Example |
|----------|---|---|
| =        | Equal to | salary = 50000 |
| <>       | Not equal to | department <> 'HR' |
| '>'      | Greater than | salary > 60000 |
| <        | Less than | salary < 60000 |
| >=       | Greater than or equal to | salary >= 60000 |
| <=       | Less than or equal to | salary <= 60000 |

**Logical Operators:**

| Operator | Description |
|---|---|
| AND | Both conditions must be true |
| OR | At least one condition must be true |
| NOT | Negates a condition |

**Example 3: Multiple Conditions**

```sql
SELECT name, salary
FROM employees
WHERE department = 'IT'
  AND salary > 60000;
```

Returns employees belonging to the IT department whose salaries exceed 60,000.

**Important:** SQL uses three-valued logic: TRUE, FALSE, and UNKNOWN. Comparisons involving `NULL` generally evaluate to UNKNOWN. Use `IS NULL` and `IS NOT NULL` when checking for missing values.

### 4. What is DISTINCT, and how does it work?

**Answer:**

`DISTINCT` eliminates duplicate rows from a query result based on the complete set of selected expressions.

Without `DISTINCT`, SQL generally returns all matching rows, including repeated values.

**Syntax:**

```sql
SELECT DISTINCT column_name
FROM table_name;
```

**Example 1: Without DISTINCT**

```sql
SELECT department
FROM employees;
```

Returns department values for all employees, including duplicates.

**Example 2: With DISTINCT**

```sql
SELECT DISTINCT department
FROM employees;
```

Returns each distinct department once.

**DISTINCT with Multiple Columns:**

```sql
SELECT DISTINCT department, city
FROM employees;
```

Returns unique combinations of departments and cities.

For example, the combinations `IT, Bengaluru` and `IT, Pune` are considered different rows.

**Important Points:**

- DISTINCT applies to the complete selected row.
- Duplicate rows are removed from the result.
- PostgreSQL treats NULL values as duplicates for duplicate elimination.
- DISTINCT does not guarantee any particular result ordering.
- Removing duplicates may require additional database processing.

**Key distinction:** `WHERE` filters rows based on conditions, while `DISTINCT` removes duplicate result rows.

### 5. What is the difference between ORDER BY and LIMIT?

**Answer:**

`ORDER BY` and `LIMIT` control the ordering and maximum number of rows returned by a SQL query.

**ORDER BY**

The `ORDER BY` clause sorts query results using one or more columns or expressions.

Sorting directions:

- `ASC`: Ascending order (default).
- `DESC`: Descending order.

**Example:**

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC;
```

Returns employees sorted from highest to lowest salary.

**LIMIT**

The `LIMIT` clause restricts the maximum number of rows returned.

**Example:**

```sql
SELECT name, salary
FROM employees
LIMIT 5;
```

Returns at most five employees. Without `ORDER BY`, the specific rows returned are not guaranteed.

**Combining ORDER BY and LIMIT:**

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC, emp_id ASC
LIMIT 3;
```

Returns the three highest-paid employees.

When employees have equal salaries, their employee IDs determine the order.

**Comparison:**

| Feature | ORDER BY | LIMIT |
|---|---|---|
| Purpose | Sorts query results | Restricts returned rows |
| Controls row ordering | Yes | No |
| Controls maximum row count | No | Yes |
| Common application | Sorting and ranking | Top-N queries and pagination |

**Important Points:**

- ORDER BY supports multiple sorting columns.
- ASC is the default sorting direction.
- LIMIT without ORDER BY does not guarantee a predictable subset.
- PostgreSQL supports OFFSET for skipping rows.
- Using a unique tie-breaker ensures deterministic ordering.
