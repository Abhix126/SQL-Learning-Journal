## 1. Theoretical Questions

### 1. What is NULL in SQL? How is it different from zero, an empty string, and FALSE? Explain SQL's three-valued logic.

**Answer:**

`NULL` is a special marker in SQL representing a missing, unknown, or inapplicable value.

It is not an ordinary value and should not be confused with zero, an empty string, or the Boolean value `FALSE`.

| Expression | Meaning |
|---|---|
| `NULL` | Missing or unknown value |
| `0` | Known numeric value equal to zero |
| `''` | Known string containing no characters |
| `FALSE` | Known Boolean false value |

SQL uses **three-valued logic**:

1. `TRUE`
2. `FALSE`
3. `UNKNOWN`

Most ordinary comparisons involving `NULL` produce `UNKNOWN`, rather than `TRUE` or `FALSE`.

For example:

```sql
SELECT
    10 = NULL AS comparison_one,
    10 <> NULL AS comparison_two,
    NULL = NULL AS comparison_three;
```

All three expressions evaluate to `NULL`, representing an unknown truth value.

**Example:**

```sql
SELECT
    emp_id,
    name,
    bonus
FROM public.employee_day4
WHERE bonus IS NULL;
```

This returns employees whose bonus information is missing.

**Important Points:**

- `NULL` is not equal to zero.
- `NULL` is not an empty string.
- Use `IS NULL` and `IS NOT NULL` to test for missing values.
- `WHERE` retains only rows whose condition evaluates to `TRUE`.
- Both `FALSE` and `UNKNOWN` conditions are excluded by `WHERE`.
- `COUNT(column)` ignores `NULL`, whereas `COUNT(*)` includes every row.

### 2. What are IS NULL, IS NOT NULL, and IS DISTINCT FROM? How do they differ from ordinary comparison operators?

**Answer:**

`IS NULL` checks whether an expression contains a SQL `NULL`.

`IS NOT NULL` checks whether an expression contains a non-`NULL` value.

Ordinary equality and inequality operators do not work as expected when comparing missing values.

**Incorrect:**

```sql
SELECT *
FROM public.employee_day4
WHERE bonus = NULL;
```

This does not identify missing bonuses because `bonus = NULL` evaluates to `UNKNOWN`.

**Correct:**

```sql
SELECT
    emp_id,
    name,
    bonus
FROM public.employee_day4
WHERE bonus IS NULL;
```

To retrieve employees with recorded bonuses:

```sql
SELECT
    emp_id,
    name,
    bonus
FROM public.employee_day4
WHERE bonus IS NOT NULL;
```

PostgreSQL also supports `IS DISTINCT FROM` and `IS NOT DISTINCT FROM`, which provide NULL-aware comparisons.

**Example:**

```sql
SELECT
    NULL IS DISTINCT FROM NULL AS result_one,
    NULL IS DISTINCT FROM 5000 AS result_two,
    NULL IS NOT DISTINCT FROM NULL AS result_three;
```

**Expected Output:**

| result_one | result_two | result_three |
|---|---|---|
| false | true | true |

Unlike ordinary equality, these operators always return `TRUE` or `FALSE`, even when operands contain `NULL`.

**Important Points:**

- Use `IS NULL` to find missing values.
- Use `IS NOT NULL` to find recorded values.
- Avoid `= NULL` and `<> NULL`.
- `IS DISTINCT FROM` treats two `NULL` values as not distinct.
- `IS NOT DISTINCT FROM` provides NULL-safe equality.

### 3. What are COALESCE() and NULLIF() in PostgreSQL? Explain their syntax, differences, and practical applications.

**Answer:**

`COALESCE()` and `NULLIF()` are SQL conditional expressions used to handle missing values and specific comparison conditions.

**COALESCE()**

`COALESCE()` returns the first non-`NULL` expression from its arguments.

**Syntax:**

```sql
COALESCE(expression1, expression2, ..., default_value)
```

**Example:**

```sql
SELECT
    emp_id,
    name,
    salary,
    bonus,
    salary + COALESCE(bonus, 0) AS total_compensation
FROM public.employee_day4;
```

When `bonus` is `NULL`, `COALESCE(bonus, 0)` substitutes zero for the calculation.

It does not modify the stored bonus value.

**NULLIF()**

`NULLIF(a, b)` returns `NULL` when `a` and `b` are equal. Otherwise, it returns `a`.

**Syntax:**

```sql
NULLIF(expression1, expression2)
```

**Example:**

```sql
SELECT
    NULLIF(10, 10) AS result_one,
    NULLIF(10, 20) AS result_two;
```

**Expected Output:**

| result_one | result_two |
|---|---|
| NULL | 10 |

A common use is preventing division by zero:

```sql
SELECT
    100.0 / NULLIF(0, 0) AS safe_division;
```

The result is `NULL`, rather than a division-by-zero error.

**Comparison:**

| Feature | COALESCE() | NULLIF() |
|---|---|---|
| Purpose | Find the first non-NULL value | Return NULL when two values are equal |
| Arguments | Two or more expressions | Exactly two expressions |
| Typical use | Default values, missing bonuses | Division-by-zero protection, sentinel values |
| Return behavior | First non-NULL argument | NULL or first argument |

**Important Points:**

- `COALESCE()` is useful for calculations involving nullable columns.
- `NULLIF()` can convert a particular value into `NULL`.
- Both are conditional expressions supported by PostgreSQL.
- Compatible data types are required for their arguments.
- Neither expression changes stored data unless used in an explicit data-modification statement.

### 4. What is the CASE expression in SQL? Explain simple CASE, searched CASE, evaluation order, and ELSE.

**Answer:**

`CASE` provides conditional logic inside SQL expressions.

It allows a query to return different values depending on specified conditions.

There are two common forms.

**A. Searched CASE**

This form evaluates Boolean conditions.

**Syntax:**

```sql
CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ELSE default_result
END
```

**Example:**

```sql
SELECT
    emp_id,
    name,
    salary,
    CASE
        WHEN salary >= 80000 THEN 'High'
        WHEN salary >= 60000 THEN 'Medium'
        ELSE 'Low'
    END AS salary_category
FROM public.employee_day4;
```

The conditions are tested in order. The result associated with the first matching condition is returned.

**B. Simple CASE**

This form compares an expression against specified values.

**Example:**

```sql
SELECT
    name,
    department,
    CASE department
        WHEN 'IT' THEN 'Technology'
        WHEN 'HR' THEN 'Human Resources'
        WHEN 'Finance' THEN 'Financial Operations'
        ELSE 'Other Department'
    END AS department_description
FROM public.employee_day4;
```

**Comparison:**

| Simple CASE | Searched CASE |
|---|---|
| Compares one expression with values | Evaluates independent conditions |
| Useful for exact matches | Useful for ranges and complex conditions |
| Uses `CASE expression` | Uses `CASE WHEN condition` |

**Important Points:**

- `CASE` is an expression, not a procedural loop.
- Conditions are evaluated in the order written for selecting the result.
- The first matching `WHEN` determines the returned result.
- `ELSE` is optional.
- Without `ELSE`, unmatched rows produce `NULL`.
- The returned expressions must have compatible data types.
- `CASE` does not automatically update the original table.

### 5. What is conditional aggregation? How can CASE, COUNT(), SUM(), and PostgreSQL FILTER be used to calculate conditional statistics?

**Answer:**

Conditional aggregation calculates summary values for selected categories or conditions within a query.

It combines aggregate functions with conditional expressions.

For example, we may want to count how many employees belong to different salary categories within each department.

**Example using CASE and SUM():**

```sql
SELECT
    department,
    COUNT(*) AS total_employees,
    SUM(
        CASE
            WHEN salary >= 70000 THEN 1
            ELSE 0
        END
    ) AS high_salary_employees
FROM public.employee_day4
GROUP BY department
ORDER BY department;
```

**How it works:**

1. `GROUP BY department` creates department groups.
2. `CASE` produces `1` for employees earning at least 70,000.
3. Other employees receive `0`.
4. `SUM()` adds those values within each group.
5. The result is the count of employees satisfying the condition.

PostgreSQL also supports the `FILTER` clause.

**Equivalent Example:**

```sql
SELECT
    department,
    COUNT(*) AS total_employees,
    COUNT(*) FILTER (
        WHERE salary >= 70000
    ) AS high_salary_employees
FROM public.employee_day4
GROUP BY department
ORDER BY department;
```

**Comparison:**

| Technique | Purpose |
|---|---|
| `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` | Conditional counting |
| `COUNT(*) FILTER (WHERE ...)` | Conditional counting using PostgreSQL syntax |
| `SUM(CASE WHEN ... THEN amount ELSE 0 END)` | Conditional summation |
| `AVG(value) FILTER (WHERE ...)` | Conditional averaging |

**Important Points:**

- Conditional aggregation calculates multiple statistics in a single grouped query.
- `CASE` can convert conditions into numeric values for aggregation.
- PostgreSQL's `FILTER` clause is useful for readable conditional aggregates.
- `WHERE` filters rows from the entire query before grouping.
- `FILTER (WHERE ...)` applies a condition only to the aggregate function it belongs to.
- `HAVING` filters complete groups after aggregation.

## 2. Practical SQL Query Challenges

**Table:** `employee_day4`

**Dataset:** `employee_day4.csv`

**Total Records:** 30

### Dataset Structure

| Column | PostgreSQL Data Type | Description |
|---|---|---|
| emp_id | INTEGER PRIMARY KEY | Unique employee identifier |
| name | VARCHAR(100) | Employee name |
| department | VARCHAR(50) | Department name |
| salary | INTEGER | Monthly salary |
| city | VARCHAR(50) | Work location |
| experience_years | INTEGER | Years of experience |
| bonus | INTEGER | Optional bonus; may be NULL |
| performance_rating | INTEGER | Rating from 1 to 5; may be NULL |

**Dataset characteristics:**

- Four departments: IT, HR, Finance, and Marketing.
- Multiple cities and salary ranges.
- Some employees have missing bonus values.
- Some employees have missing performance ratings.
- Both nullable columns must preserve actual SQL `NULL` values.

### Query Challenges

**1. Identify employees with missing compensation or performance information.**

Retrieve `emp_id`, `name`, `department`, `bonus`, and `performance_rating` for employees whose bonus or performance rating is `NULL`.

Sort the results by `department ASC`, followed by `emp_id ASC`.

**Concepts:** `IS NULL`, `OR`, `ORDER BY`.

**2. Calculate employee compensation using COALESCE().**

Retrieve `emp_id`, `name`, `department`, `salary`, `bonus`, and a calculated column named `total_compensation`.

Calculate total compensation as salary plus bonus, treating missing bonuses as zero without modifying the original table.

Display only employees with total compensation of at least 75,000.

Sort by `total_compensation DESC`, then `emp_id ASC`.

**Concepts:** `COALESCE()`, arithmetic expressions, filtering calculated results.

**3. Categorize employees using CASE expressions.**

Retrieve `emp_id`, `name`, `department`, `salary`, and a calculated column named `salary_category`.

Apply these classifications:

| Condition | Salary Category |
|---|---|
| Salary >= 80000 | High |
| Salary >= 60000 and < 80000 | Medium |
| Salary < 60000 | Low |

Sort by `salary DESC`, followed by `emp_id ASC`.

**Concepts:** Searched `CASE`, conditional ranges, `ELSE`.

**4. Calculate department-wise employee statistics using conditional aggregation.**

For each department, retrieve:

- `department`
- `total_employees`
- `high_salary_employees` — employees earning at least 70,000
- `employees_with_bonus` — employees whose bonus is not NULL
- `employees_without_rating` — employees whose performance rating is NULL

Use aggregate functions with `CASE` expressions or PostgreSQL's `FILTER` clause.

Sort by `high_salary_employees DESC`, then `department ASC`.

**Concepts:** `GROUP BY`, `COUNT()`, `CASE`, conditional aggregation, `FILTER`.

**5. Analyze performance ratings and compensation by department.**

For each department, retrieve:

- `department`
- `rated_employees` — number of employees with a recorded performance rating
- `average_rating` — average of non-NULL ratings, rounded to two decimal places
- `total_bonus` — sum of recorded bonuses, displaying zero if the sum is NULL
- `performance_category` — classify the department according to its average recorded rating:

| Average Rating | Performance Category |
|---|---|
| >= 4.00 | Excellent |
| >= 3.00 and < 4.00 | Good |
| < 3.00 | Needs Improvement |
| No recorded ratings | Not Rated |

Include only departments having at least four employees with recorded performance ratings.

Sort by `average_rating DESC`, followed by `department ASC`.

**Concepts:** `AVG()`, `ROUND()`, `COALESCE()`, `CASE`, `GROUP BY`, `HAVING`, `NULL` handling.
