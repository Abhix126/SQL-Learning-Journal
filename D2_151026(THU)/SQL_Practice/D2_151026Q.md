### 1. What are comparison operators in SQL, and how are they used to filter records?

**Answer:**

Comparison operators are used in SQL to compare values, columns, or expressions. They are commonly used with the `WHERE` clause to retrieve rows that satisfy specific conditions.

SQL comparison expressions generally produce one of three logical results:

- `TRUE`: The condition is satisfied.
- `FALSE`: The condition is not satisfied.
- `UNKNOWN`: The result cannot be determined, typically because a comparison involves `NULL`.

**Comparison Operators:**

| Operator | Meaning | Example |
|---|---|---|
| = | Equal to | salary = 60000 |
| <> | Not equal to | department <> 'HR' |
| != | Not equal to (PostgreSQL alternative) | city != 'Delhi' |
| > | Greater than | salary > 60000 |
| < | Less than | salary < 60000 |
| >= | Greater than or equal to | salary >= 60000 |
| <= | Less than or equal to | salary <= 60000 |

**Syntax:**

```sql
SELECT column1, column2
FROM table_name
WHERE column_name comparison_operator value;
```

**Example 1: Equality Comparison**

```sql
SELECT name, department
FROM employees
WHERE department = 'IT';
```

Retrieves employees belonging to the IT department.

**Example 2: Greater Than or Equal To**

```sql
SELECT name, salary
FROM employees
WHERE salary >= 60000;
```

Retrieves employees whose salaries are greater than or equal to 60,000.

**Example 3: Inequality Comparison**

```sql
SELECT name, city
FROM employees
WHERE city <> 'Mumbai';
```

Retrieves employees whose cities are not Mumbai, excluding rows where `city` is `NULL`.

**Example 4: Comparing Two Columns**

Assume an `employee_targets` table contains `actual_sales` and `target_sales` columns.

```sql
SELECT employee_id, actual_sales, target_sales
FROM employee_targets
WHERE actual_sales > target_sales;
```

Retrieves employees whose actual sales exceed their assigned targets.

**Comparison with NULL:**

A `NULL` represents a missing or unknown value.

Consider:

```sql
SELECT name
FROM employees
WHERE salary = NULL;
```

This does not correctly identify missing salaries because comparing a value with `NULL` using `=` produces `UNKNOWN`.

The correct approach is:

```sql
SELECT name
FROM employees
WHERE salary IS NULL;
```

Similarly:

```sql
SELECT name
FROM employees
WHERE salary IS NOT NULL;
```

Retrieves employees whose salary values are not `NULL`.

**Important Points:**

- Comparison operators are commonly used with `WHERE`, `HAVING`, and conditional expressions.
- PostgreSQL supports both `<>` and `!=` for inequality.
- `<>` is the standard SQL inequality operator.
- Numeric values are compared according to their numeric values.
- Text comparisons depend on the database's collation and comparison rules.
- Ordinary comparisons involving `NULL` generally produce `UNKNOWN`.
- The `WHERE` clause retains only rows whose condition evaluates to `TRUE`.

**Key distinction:** Comparison operators evaluate relationships between values, while the `WHERE` clause uses those conditions to determine which rows are returned.

### 2. What are logical operators in SQL, and how do AND, OR, and NOT work with operator precedence?

**Answer:**

Logical operators are used to combine or negate conditions in SQL queries.

They allow multiple filtering requirements to be expressed within a single `WHERE` clause.

The three primary logical operators are:

| Operator | Description |
|---|---|
| AND | Returns TRUE when both conditions are TRUE |
| OR | Returns TRUE when at least one condition is TRUE |
| NOT | Negates the logical result of a condition |

**AND Operator:**

The `AND` operator requires both conditions to be satisfied.

**Example:**

```sql
SELECT name, department, salary
FROM employees
WHERE department = 'IT'
  AND salary > 60000;
```

Retrieves employees who belong to IT and earn more than 60,000.

If either condition evaluates to `FALSE`, the combined condition evaluates to `FALSE`.

**OR Operator:**

The `OR` operator requires at least one condition to be satisfied.

**Example:**

```sql
SELECT name, department
FROM employees
WHERE department = 'IT'
   OR department = 'Finance';
```

Retrieves employees belonging to either IT or Finance.

**NOT Operator:**

The `NOT` operator reverses the logical result of a condition.

**Example:**

```sql
SELECT name, department
FROM employees
WHERE NOT (department = 'HR');
```

Retrieves employees who do not belong to HR, excluding rows where the condition is `UNKNOWN`.

**Truth Table:**

| Condition A | Condition B | A AND B | A OR B |
|---|---|---|---|
| TRUE | TRUE | TRUE | TRUE |
| TRUE | FALSE | FALSE | TRUE |
| FALSE | TRUE | FALSE | TRUE |
| FALSE | FALSE | FALSE | FALSE |

**SQL Three-Valued Logic:**

Unlike ordinary Boolean logic, SQL also supports `UNKNOWN`.

| Expression | Result |
|---|---|
| TRUE AND UNKNOWN | UNKNOWN |
| FALSE AND UNKNOWN | FALSE |
| TRUE OR UNKNOWN | TRUE |
| FALSE OR UNKNOWN | UNKNOWN |
| NOT UNKNOWN | UNKNOWN |

**Operator Precedence:**

For logical operators, PostgreSQL evaluates expressions in the following order:

1. `NOT`
2. `AND`
3. `OR`

Parentheses can be used to explicitly control the grouping of conditions.

**Example 1: Without Parentheses**

```sql
SELECT name, department, salary
FROM employees
WHERE department = 'IT'
   OR department = 'HR'
  AND salary > 50000;
```

Because `AND` has higher precedence than `OR`, PostgreSQL interprets the condition as:

```sql
WHERE department = 'IT'
   OR (department = 'HR' AND salary > 50000)
```

This retrieves all IT employees, regardless of salary, along with HR employees earning more than 50,000.

**Example 2: With Parentheses**

```sql
SELECT name, department, salary
FROM employees
WHERE (department = 'IT' OR department = 'HR')
  AND salary > 50000;
```

This retrieves only IT or HR employees whose salaries exceed 50,000.

**Important Points:**

- `AND` combines conditions that must all be satisfied.
- `OR` combines alternative conditions.
- `NOT` negates a condition.
- `AND` has higher precedence than `OR`.
- Parentheses make complex filtering conditions easier to understand.
- SQL uses three-valued logic when `NULL` values are involved.
- The `WHERE` clause excludes rows whose conditions evaluate to `FALSE` or `UNKNOWN`.

**Key distinction:** `AND` narrows results by requiring multiple conditions, while `OR` broadens results by accepting alternatives. `NOT` reverses a condition.

### 3. What are BETWEEN and NOT BETWEEN in SQL, and how do they handle range boundaries?

**Answer:**

The `BETWEEN` operator is used to determine whether a value falls within a specified range.

It is commonly used with numeric values, dates, and other comparable data types.

**Syntax:**

```sql
SELECT column_name
FROM table_name
WHERE column_name BETWEEN lower_bound AND upper_bound;
```

**BETWEEN Operator:**

`BETWEEN` includes both the lower and upper boundaries.

**Example 1: Salary Range**

```sql
SELECT name, salary
FROM employees
WHERE salary BETWEEN 50000 AND 75000;
```

Retrieves employees whose salaries are between 50,000 and 75,000, including both values.

For ordinary non-NULL numeric values, the condition is equivalent to:

```sql
WHERE salary >= 50000
  AND salary <= 75000
```

**NOT BETWEEN Operator:**

`NOT BETWEEN` selects values that fall outside the specified range.

**Example 2: Excluding a Salary Range**

```sql
SELECT name, salary
FROM employees
WHERE salary NOT BETWEEN 50000 AND 75000;
```

Retrieves employees earning less than 50,000 or more than 75,000.

For ordinary non-NULL numeric values, the condition is equivalent to:

```sql
WHERE salary < 50000
   OR salary > 75000
```

**Boundary Inclusivity:**

Consider these salary values:

| Salary | BETWEEN 50000 AND 75000 | NOT BETWEEN 50000 AND 75000 |
|---|---|---|
| 45000 | FALSE | TRUE |
| 50000 | TRUE | FALSE |
| 60000 | TRUE | FALSE |
| 75000 | TRUE | FALSE |
| 80000 | FALSE | TRUE |

Both boundaries are included when using `BETWEEN`.

**Example 3: Combining BETWEEN with AND**

```sql
SELECT name, salary, experience_years
FROM employees
WHERE salary BETWEEN 50000 AND 80000
  AND experience_years >= 5;
```

Retrieves employees earning between 50,000 and 80,000 who have at least five years of experience.

**Example 4: Date Filtering**

Assume an `orders` table contains an `order_date` column of type `DATE`.

```sql
SELECT order_id, order_date
FROM orders
WHERE order_date BETWEEN '2026-10-01' AND '2026-10-15';
```

Retrieves orders dated from 1 October through 15 October 2026, including both dates.

**Important Consideration for Timestamps:**

If a column stores timestamps instead of dates, using an inclusive upper boundary at midnight can unintentionally exclude records later on the final day.

For timestamp filtering, a half-open interval is often preferable:

```sql
SELECT order_id, order_timestamp
FROM orders
WHERE order_timestamp >= '2026-10-01'
  AND order_timestamp < '2026-10-16';
```

This includes timestamps on 15 October while excluding timestamps from 16 October onward.

**Important Points:**

- `BETWEEN` includes both boundary values.
- `NOT BETWEEN` selects values outside the range.
- The lower boundary should normally be less than or equal to the upper boundary.
- `BETWEEN` can be used with numbers, dates, and other comparable types.
- Comparisons involving `NULL` may produce `UNKNOWN`.
- Explicit comparison operators can be used when exclusive boundaries are required.
- Timestamp filtering should account for time components.

**Key distinction:** `BETWEEN` checks whether a value lies inside an inclusive range, whereas `NOT BETWEEN` checks whether it lies outside that range.

### 4. What are IN and NOT IN operators in SQL, and how do they differ from multiple OR and AND conditions?

**Answer:**

The `IN` operator checks whether a value matches any value in a specified list or the result of a subquery.

The `NOT IN` operator checks whether a value does not match any value in the specified list or subquery result.

These operators provide a concise alternative to writing multiple equality or inequality comparisons.

**IN Syntax:**

```sql
SELECT column_name
FROM table_name
WHERE column_name IN (value1, value2, value3);
```

**Example 1: IN Operator**

```sql
SELECT name, department
FROM employees
WHERE department IN ('IT', 'HR', 'Finance');
```

Retrieves employees belonging to IT, HR, or Finance.

For non-NULL values, this is equivalent to:

```sql
SELECT name, department
FROM employees
WHERE department = 'IT'
   OR department = 'HR'
   OR department = 'Finance';
```

**NOT IN Syntax:**

```sql
SELECT column_name
FROM table_name
WHERE column_name NOT IN (value1, value2, value3);
```

**Example 2: NOT IN Operator**

```sql
SELECT name, city
FROM employees
WHERE city NOT IN ('Delhi', 'Mumbai');
```

Retrieves employees whose cities are neither Delhi nor Mumbai, excluding `NULL` cities.

For non-NULL values, this is equivalent to:

```sql
SELECT name, city
FROM employees
WHERE city <> 'Delhi'
  AND city <> 'Mumbai';
```

**Comparison:**

| Feature | IN | NOT IN |
|---|---|---|
| Purpose | Matches one or more specified values | Excludes specified values |
| Logical equivalent | Multiple OR comparisons | Multiple AND inequality comparisons |
| Supports multiple values | Yes | Yes |
| Supports subqueries | Yes | Yes |
| Common use | Including selected categories | Excluding selected categories |

**Example 3: Combining IN with AND**

```sql
SELECT name, department, salary
FROM employees
WHERE department IN ('IT', 'Finance')
  AND salary > 60000;
```

Retrieves IT or Finance employees earning more than 60,000.

**Example 4: IN with a Subquery**

Assume another table named `active_departments` contains a `department_name` column.

```sql
SELECT name, department
FROM employees
WHERE department IN (
    SELECT department_name
    FROM active_departments
);
```

Retrieves employees whose departments appear in the `active_departments` table.

**Important NULL Behavior:**

Consider:

```sql
SELECT name, department
FROM employees
WHERE department NOT IN ('HR', NULL);
```

For any non-NULL department other than HR, the comparison with `NULL` produces `UNKNOWN`.

As a result, this condition does not evaluate to `TRUE` for any row.

This is a common problem when `NOT IN` is used with subqueries that may return `NULL`.

**Example 5: NOT EXISTS Alternative**

Assume the `excluded_departments` table contains a `department_name` column.

```sql
SELECT e.name, e.department
FROM employees AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM excluded_departments AS d
    WHERE d.department_name = e.department
);
```

This retrieves employees for whom no matching department exists in the exclusion table.

Unlike `NOT IN`, a `NULL` inside `excluded_departments.department_name` does not automatically prevent unrelated employees from being returned.

**Important Points:**

- `IN` is useful when comparing a value against multiple alternatives.
- `NOT IN` excludes values appearing in a specified list.
- Both operators can accept subqueries.
- `IN` often improves readability compared with repeated `OR` conditions.
- `NOT IN` is logically similar to repeated inequality conditions for non-NULL values.
- `NULL` values can affect the behavior of `IN` and `NOT IN`.
- `NOT EXISTS` is often preferable for exclusion subqueries that may contain `NULL`.

**Key distinction:** `IN` checks membership in a collection of values, while `NOT IN` checks non-membership, subject to SQL's three-valued logic.

### 5. What is the LIKE operator in SQL, and how are wildcards used for pattern matching?

**Answer:**

The `LIKE` operator is used to search for text values that match a specified pattern.

It is commonly used with the `WHERE` clause to filter records based on partial text matches.

Unlike the equality operator (`=`), which compares complete values, `LIKE` supports wildcard characters.

**Syntax:**

```sql
SELECT column_name
FROM table_name
WHERE column_name LIKE 'pattern';
```

**LIKE Wildcards:**

| Wildcard | Meaning | Example |
|---|---|---|
| % | Matches zero or more characters | 'A%' |
| _ | Matches exactly one character | 'A_' |

**Example 1: Names Starting with A**

```sql
SELECT name
FROM employees
WHERE name LIKE 'A%';
```

Retrieves employees whose names begin with the letter A.

Examples of matching names include `Amit`, `Arjun`, and `Ananya`.

**Example 2: Names Ending with a**

```sql
SELECT name
FROM employees
WHERE name LIKE '%a';
```

Retrieves employees whose names end with the letter `a`.

**Example 3: Names Containing a Substring**

```sql
SELECT name
FROM employees
WHERE name LIKE '%an%';
```

Retrieves names containing the sequence `an`.

**Example 4: Matching a Single Character**

```sql
SELECT name
FROM employees
WHERE name LIKE '_a%';
```

Retrieves names whose second character is `a`.

The underscore represents exactly one character.

**Example 5: NOT LIKE**

```sql
SELECT name
FROM employees
WHERE name NOT LIKE 'S%';
```

Retrieves employees whose names do not start with S, excluding `NULL` names.

**Example 6: Combining LIKE with Logical Operators**

```sql
SELECT name, city
FROM employees
WHERE name LIKE 'A%'
  AND city LIKE 'B%';
```

Retrieves employees whose names begin with A and whose cities begin with B.

**Case Sensitivity in PostgreSQL:**

PostgreSQL distinguishes between `LIKE` and `ILIKE`.

- `LIKE` performs pattern matching that is normally case-sensitive under deterministic collations.
- `ILIKE` performs case-insensitive pattern matching according to the active locale.

**Example 7: LIKE**

```sql
SELECT name
FROM employees
WHERE name LIKE 'a%';
```

Under a typical case-sensitive collation, this matches names beginning with lowercase `a`, not uppercase `A`.

**Example 8: ILIKE**

```sql
SELECT name
FROM employees
WHERE name ILIKE 'a%';
```

This performs case-insensitive matching and can retrieve names beginning with either uppercase A or lowercase a.

**Example 9: Matching a Literal Wildcard**

Wildcards can be escaped when they need to be treated as ordinary characters.

Assume a `products` table contains a `product_name` column.

```sql
SELECT product_name
FROM products
WHERE product_name LIKE '%!%%' ESCAPE '!';
```

This retrieves product names containing a literal percent sign.

**Comparison:**

| Operator | Purpose |
|---|---|
| = | Exact value comparison |
| LIKE | Pattern matching |
| NOT LIKE | Excludes matching patterns |
| ILIKE | Case-insensitive pattern matching in PostgreSQL |
| NOT ILIKE | Excludes case-insensitive pattern matches |

**Important Points:**

- `%` matches zero or more characters.
- `_` matches exactly one character.
- `LIKE` performs text pattern matching.
- `NOT LIKE` negates a pattern match.
- PostgreSQL supports `ILIKE` for case-insensitive matching.
- `NULL` values do not produce a TRUE result with ordinary `LIKE` comparisons.
- Patterns beginning with `%` may prevent efficient use of ordinary B-tree indexes.
- Wildcard characters can be escaped to match them literally.

**Key distinction:** The equality operator compares complete values, whereas `LIKE` searches for values matching a specified text pattern.
