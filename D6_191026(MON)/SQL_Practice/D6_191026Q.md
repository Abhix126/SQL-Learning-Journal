## 1. Theoretical Questions

### 1. What is a SELF JOIN in SQL? How does it work, and why is it useful for hierarchical relationships?

**Answer:**

A `SELF JOIN` is a technique in which a table is joined with itself using two different aliases.

It is useful when records within the same table are related to one another.

Common examples include:

- Employees and their managers.
- Students and their mentors.
- Categories and their parent categories.
- Users and their referrals.
- Organizational reporting hierarchies.

Consider an employee table containing a `manager_id` column that references another employee's `emp_id`.

**Example Table: employees**

| emp_id | name | manager_id |
|---|---|---|
| 101 | Amit | NULL |
| 102 | Priya | 101 |
| 103 | Rahul | 101 |
| 104 | Sneha | 102 |

Here, Amit manages Priya and Rahul, while Priya manages Sneha.

**SQL Query:**

```sql
SELECT
    e.emp_id,
    e.name AS employee_name,
    m.name AS manager_name
FROM employees AS e
LEFT JOIN employees AS m
    ON e.manager_id = m.emp_id;
```

**Expected Output:**

| emp_id | employee_name | manager_name |
|---|---|---|
| 101 | Amit | NULL |
| 102 | Priya | Amit |
| 103 | Rahul | Amit |
| 104 | Sneha | Priya |

**Explanation:**

1. `employees AS e` represents employees.
2. `employees AS m` represents managers.
3. Both aliases refer to the same physical table.
4. The join condition matches an employee's `manager_id` with the manager's `emp_id`.
5. `LEFT JOIN` preserves employees without managers.

**Important Points:**

- SELF JOIN is a technique, not a separate SQL JOIN keyword.
- A table is referenced more than once using different aliases.
- SELF JOIN can use INNER JOIN, LEFT JOIN, or other supported JOIN types.
- SELF JOIN is commonly used for employee-manager relationships.
- INNER JOIN excludes employees without matching managers.
- LEFT JOIN preserves employees without managers.
- A self-referencing foreign key can enforce valid manager relationships.

### 2. What are Equi JOIN and Non-Equi JOIN? Explain their differences with examples.

**Answer:**

Equi JOIN and Non-Equi JOIN describe how tables are matched based on their join conditions.

**Equi JOIN:**

An Equi JOIN uses equality (`=`) to match records between tables.

**Example:**

```sql
SELECT
    e.name,
    d.department_name
FROM employees AS e
INNER JOIN departments AS d
    ON e.department_id = d.department_id;
```

This retrieves employees whose department IDs match department records.

**Non-Equi JOIN:**

A Non-Equi JOIN uses comparison operators other than equality, such as:

- `<`
- `>`
- `<=`
- `>=`
- `<>`
- `BETWEEN`

**Example:**

Suppose a salary grade table contains:

| grade | min_salary | max_salary |
|---|---|---|
| Junior | 30000 | 49999 |
| Mid-Level | 50000 | 79999 |
| Senior | 80000 | 120000 |

We can match employees to salary grades using salary ranges.

```sql
SELECT
    e.emp_id,
    e.name,
    e.salary,
    g.grade
FROM employees AS e
INNER JOIN salary_grades AS g
    ON e.salary BETWEEN g.min_salary AND g.max_salary;
```

**Comparison:**

| Feature | Equi JOIN | Non-Equi JOIN |
|---|---|---|
| Matching condition | Equality | Inequality or range conditions |
| Common operators | `=` | `<`, `>`, `<=`, `>=`, `BETWEEN` |
| Common use | Primary key–foreign key relationships | Salary bands, date ranges, comparisons |
| Matching rows | Equal key values | Values satisfying a comparison condition |

**Important Points:**

- Equi JOIN is commonly used for relational key matching.
- Non-Equi JOIN is useful for range-based relationships.
- Non-Equi JOIN can produce multiple matches if ranges overlap.
- JOIN conditions are not restricted to primary and foreign keys.
- `BETWEEN` includes both boundary values.
- Carefully design salary ranges to avoid unintended overlapping matches.

### 3. What are composite JOIN conditions? How can multiple conditions be combined using AND and OR?

**Answer:**

A composite JOIN condition uses more than one condition to determine whether rows should match.

Conditions are commonly combined using `AND` or `OR`.

**Example:**

Suppose employee assignments and project records share two matching columns:

- `project_id`
- `department_id`

A JOIN can match both values.

```sql
SELECT
    a.emp_id,
    a.project_id,
    p.project_name
FROM employee_assignments AS a
INNER JOIN projects AS p
    ON a.project_id = p.project_id
   AND a.department_id = p.department_id;
```

**Explanation:**

- `AND` requires both conditions to be satisfied.
- `OR` allows either condition to be satisfied.
- Multiple conditions help define more specific relationships.
- An incorrect join condition can produce unintended duplicates.

**Example using an additional filtering condition:**

```sql
SELECT
    e.name,
    p.project_name,
    p.status
FROM employees AS e
INNER JOIN projects AS p
    ON e.emp_id = p.emp_id
   AND p.status = 'Active';
```

For this INNER JOIN, the query returns employee-project matches whose project status is Active.

**ON vs WHERE with LEFT JOIN:**

```sql
SELECT
    e.name,
    p.project_name
FROM employees AS e
LEFT JOIN projects AS p
    ON e.emp_id = p.emp_id
   AND p.status = 'Active';
```

This preserves every employee, even when they have no active project.

However:

```sql
SELECT
    e.name,
    p.project_name
FROM employees AS e
LEFT JOIN projects AS p
    ON e.emp_id = p.emp_id
WHERE p.status = 'Active';
```

This removes employees without matching active projects.

**Important Points:**

- Composite JOIN conditions use multiple logical expressions.
- `AND` requires all specified conditions to be true.
- `OR` allows matches when at least one condition is true.
- Additional conditions can make JOIN matching more precise.
- `ON` determines matching during JOIN processing.
- `WHERE` filters the joined result.
- Conditions placed in `ON` and `WHERE` can behave differently for OUTER JOINs.

### 4. What is an Anti-JOIN in SQL? How can LEFT JOIN with IS NULL and NOT EXISTS identify unmatched records?

**Answer:**

An Anti-JOIN is a query pattern that returns records from one table for which no matching records exist in another table.

PostgreSQL does not use a standalone `ANTI JOIN` keyword in ordinary SQL syntax.

Two common approaches are:

1. `LEFT JOIN` with `IS NULL`.
2. `NOT EXISTS` with a correlated subquery.

**Method 1: LEFT JOIN with IS NULL**

```sql
SELECT
    e.emp_id,
    e.name
FROM employees AS e
LEFT JOIN projects AS p
    ON e.emp_id = p.emp_id
WHERE p.project_id IS NULL;
```

This retrieves employees without assigned projects.

**Method 2: NOT EXISTS**

```sql
SELECT
    e.emp_id,
    e.name
FROM employees AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM projects AS p
    WHERE p.emp_id = e.emp_id
);
```

Both queries identify employees without matching project records.

**Explanation:**

- `LEFT JOIN` preserves employees without matching projects.
- Unmatched project columns become NULL.
- `WHERE p.project_id IS NULL` selects unmatched employees.
- `NOT EXISTS` checks whether the correlated subquery returns no rows.

**Comparison:**

| Method | Approach |
|---|---|
| LEFT JOIN + IS NULL | Find NULL-extended rows after an outer join |
| NOT EXISTS | Test whether matching rows do not exist |
| NOT IN | Exclude matching values, but requires careful NULL handling |

**Important Points:**

- Anti-joins are useful for finding missing relationships.
- `LEFT JOIN ... IS NULL` is a common anti-join pattern.
- `NOT EXISTS` is often clear and reliable for checking missing relationships.
- `NOT IN` can behave unexpectedly if its subquery returns NULL.
- Use a non-nullable right-table key when identifying unmatched rows with `IS NULL`.
- Anti-joins are useful for finding employees without projects, customers without orders, and products without sales.

### 5. How can SELF JOINs be used for comparisons within the same table? Explain duplicate pairs, inequality conditions, and performance considerations.

**Answer:**

SELF JOINs can compare different rows within the same table.

For example, we may want to identify employees working in the same department or employees earning more than their managers.

**Example 1: Employees earning more than their managers**

```sql
SELECT
    e.name AS employee_name,
    e.salary AS employee_salary,
    m.name AS manager_name,
    m.salary AS manager_salary
FROM employees AS e
INNER JOIN employees AS m
    ON e.manager_id = m.emp_id
WHERE e.salary > m.salary;
```

**Explanation:**

1. The first alias represents employees.
2. The second alias represents managers.
3. The JOIN matches each employee with their manager.
4. `WHERE` compares the employee's salary with the manager's salary.
5. Only employees earning more than their managers are returned.

**Example 2: Employee pairs from the same department**

```sql
SELECT
    e1.name AS employee_one,
    e2.name AS employee_two,
    e1.department_id
FROM employees AS e1
INNER JOIN employees AS e2
    ON e1.department_id = e2.department_id
   AND e1.emp_id < e2.emp_id;
```

**Why use `e1.emp_id < e2.emp_id`?**

Without this condition, the query could produce:

- Amit–Rahul
- Rahul–Amit
- Amit–Amit
- Rahul–Rahul

Using `<` prevents self-pairs and reversed duplicate pairs.

**Performance Considerations:**

- SELF JOINs can generate many row combinations.
- Missing or incorrect JOIN conditions may produce unexpectedly large results.
- Indexes on frequently joined columns can improve performance.
- Self-referencing foreign keys help maintain valid hierarchical relationships.
- Recursive CTEs are often more appropriate for traversing hierarchies with an unknown number of levels.

**Important Points:**

- SELF JOIN can compare rows within one table.
- Table aliases distinguish different references to the same table.
- Inequality conditions can compare salaries, experience, or other numeric attributes.
- `e1.emp_id < e2.emp_id` prevents duplicate unordered pairs.
- JOIN conditions should be selective and logically correct.
- Recursive CTEs are useful for exploring multi-level organizational hierarchies.

### Query Challenges

**1. Retrieve employees with their manager details using SELF JOIN.**

Retrieve:

- `emp_id`
- `employee_name`
- `employee_salary`
- `manager_name`
- `manager_salary`

Include all employees, even those without assigned managers.

Sort by `emp_id ASC`.

**Concepts:** SELF JOIN, LEFT JOIN, table aliases, self-referencing foreign keys.

**2. Identify employees earning more than their managers.**

Retrieve:

- `emp_id`
- `employee_name`
- `employee_salary`
- `manager_name`
- `manager_salary`
- `salary_difference` — employee salary minus manager salary.

Include only employees whose salary is greater than their manager's salary.

Sort by `salary_difference DESC`, followed by `emp_id ASC`.

**Concepts:** SELF JOIN, INNER JOIN, inequality comparisons, calculated columns.

**3. Assign salary grades using a Non-Equi JOIN.**

Retrieve:

- `emp_id`
- `name`
- `salary`
- `grade_name`
- `min_salary`
- `max_salary`

Match each employee to the appropriate salary grade using a range-based JOIN condition.

Include only employees whose salary falls within a defined grade.

Sort by `salary DESC`, followed by `emp_id ASC`.

**Concepts:** Non-Equi JOIN, BETWEEN, range conditions, INNER JOIN.

**4. Identify employees without active projects using an Anti-JOIN.**

Retrieve:

- `emp_id`
- `name`
- `department_id`
- `salary`

Include employees who have no projects with `status = 'Active'`.

Employees assigned only to Completed or Planning projects must also be included.

Use either:

- `LEFT JOIN` with `IS NULL`, or
- `NOT EXISTS`.

Sort by `emp_id ASC`.

**Concepts:** Anti-JOIN, NOT EXISTS, LEFT JOIN, IS NULL, composite JOIN conditions.

**5. Find unique employee pairs working in the same department.**

Retrieve:

- `department_name`
- `employee_one`
- `employee_two`
- `employee_one_salary`
- `employee_two_salary`
- `salary_difference` — absolute difference between the two salaries.

Include only employee pairs belonging to the same department.

Avoid:

- Pairing an employee with themselves.
- Returning reversed duplicate pairs.

Include only pairs whose absolute salary difference is at least 15,000.

Sort by `salary_difference DESC`, followed by `department_name ASC`, then `employee_one ASC` and `employee_two ASC`.

**Concepts:** SELF JOIN, composite JOIN conditions, inequality comparisons, ABS(), INNER JOIN, duplicate-pair prevention.
